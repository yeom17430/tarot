# AI 타로 리딩 웹사이트 제작 요구사항

## 1. 프로젝트 개요

사용자가 직접 타로카드를 섞고 원하는 카드를 선택한 뒤, 선택한 상담 주제와 질문에 맞는 AI 타로 해석을 받을 수 있는 웹사이트를 제작한다.

이 사이트에서 가장 중요한 기능과 방향은 다음과 같다.

1. 사용자가 화면에 펼쳐진 타로카드 중 원하는 카드를 직접 선택할 수 있어야 한다.
2. 카드를 선택하기 전에 실제 카드가 섞이는 듯한 셔플 애니메이션이 있어야 한다.
3. 전체 배경과 인터페이스가 실제 신비로운 타로점에 들어온 듯한 분위기를 줘야 한다.
4. 사용자가 연애운, 재물운, 진로운 등 원하는 상담 주제를 선택할 수 있어야 한다.
5. 사용자는 1장, 3장, 7장 리딩 중 원하는 카드 배열을 선택할 수 있어야 한다.
6. 선택된 카드와 상담 주제를 바탕으로 Google Gemini API가 자연스러운 타로 리딩 결과를 생성해야 한다.
7. Gemini API 키가 없거나 API 요청에 실패해도 임시 해석 결과를 제공하여 사이트의 기본 흐름이 중단되지 않아야 한다.
8. PC와 모바일 화면에서 모두 정상적으로 이용할 수 있어야 한다.
9. 디자인은 일반적인 카드 게임이 아니라 고급스럽고 몰입감 있는 타로점 분위기로 제작한다.

---

# 2. 핵심 사용자 흐름

사용자는 다음 순서로 타로 리딩을 진행한다.

```text
시작 화면
→ 상담 주제 선택
→ 질문 입력
→ 카드 수 선택
→ 카드 셔플
→ 카드 직접 선택
→ 카드 공개
→ Gemini AI 해석 생성
→ 결과 저장 또는 다시 보기
```

---

# 3. 시작 화면

처음 사이트에 접속하면 사용자가 실제 타로점 공간에 들어온 듯한 화면을 보여준다.

화면 중앙에는 다음 요소를 배치한다.

- 서비스 제목
- 간단한 안내 문구
- `타로 리딩 시작하기` 버튼
- 은은하게 움직이는 배경 효과
- 촛불
- 수정구
- 별
- 달
- 벨벳 커튼
- 오래된 나무 테이블
- 천천히 움직이는 빛이나 먼지 입자

예시 문구:

> 마음속에 질문을 떠올려보세요.  
> 카드가 당신에게 필요한 메시지를 전해드립니다.

또는:

> 조용히 마음을 가다듬고 카드의 메시지에 집중해보세요.

`타로 리딩 시작하기` 버튼을 누르면 상담 주제 선택 화면으로 이동한다.

시작 버튼에는 다음과 같은 효과를 적용한다.

- 마우스를 올리면 금색 빛이 퍼지는 효과
- 버튼 테두리가 은은하게 빛나는 효과
- 클릭 시 화면이 자연스럽게 전환되는 효과
- 지나치게 빠르거나 게임처럼 가벼운 효과는 피한다.

# 4. 상담 주제 선택

사용자가 어떤 내용에 대해 타로를 볼 것인지 선택할 수 있어야 한다.

기본 상담 주제는 다음과 같이 구성한다.

- 연애운
- 재물운
- 진로운
- 학업운
- 인간관계
- 오늘의 운세
- 상대방의 마음
- 직접 질문 입력

각 주제는 아이콘이나 작은 타로카드 형태의 버튼으로 표시한다.

예시:

- 연애운: 하트 아이콘
- 재물운: 동전 아이콘
- 진로운: 나침반 아이콘
- 학업운: 책 아이콘
- 인간관계: 사람 또는 연결 아이콘
- 오늘의 운세: 태양 아이콘
- 상대방의 마음: 달 아이콘
- 직접 질문: 수정구 아이콘

주제를 선택하면 다음 효과를 적용한다.

- 선택된 버튼의 테두리가 금색 또는 보라색으로 빛난다.
- 선택된 카드가 약간 위로 올라간다.
- 선택되지 않은 항목보다 밝게 표시된다.
- 선택된 주제 이름을 화면에 다시 보여준다.

사용자는 한 번에 하나의 주제만 선택할 수 있다.

# 5. 질문 입력

모든 주제에서 사용자가 구체적인 질문을 입력할 수 있도록 한다.

질문 입력은 필수가 아니라 선택 사항으로 제공할 수 있다.

예시 질문:

> 그 사람과 다시 연락할 가능성이 있을까요?

> 지금 준비 중인 진로를 계속 이어가도 괜찮을까요?

> 이번 달 재물 흐름에서 주의해야 할 부분은 무엇인가요?

`직접 질문 입력`을 선택한 경우 질문 입력을 필수로 설정한다.

질문 입력 규칙:

- 최소 2자 이상
- 최대 200자 이하
- 공백만 입력한 경우 허용하지 않는다.
- HTML 태그나 위험한 스크립트 입력은 서버에서 제거하거나 거부한다.
- 질문을 입력하지 않은 경우 선택한 주제를 기반으로 기본 질문을 생성한다.

기본 질문 예시:

```text
연애운 → 현재 나의 연애 흐름과 필요한 조언을 알려주세요.
재물운 → 현재 나의 재정적 흐름과 주의할 점을 알려주세요.
진로운 → 현재 진로 방향과 앞으로 고려할 점을 알려주세요.
학업운 → 현재 학업 흐름과 성장을 위한 조언을 알려주세요.
오늘의 운세 → 오늘 하루의 전반적인 흐름과 주의할 점을 알려주세요.
```

# 6. 카드 배열 선택

사용자가 원하는 타로 리딩 방식을 선택할 수 있도록 한다.

다음 세 가지 방식을 제공한다.

## 6.1 한 장 리딩

카드 한 장을 선택한다.

간단하고 빠른 메시지를 받고 싶은 사용자에게 적합하다.

다음과 같은 질문에 사용한다.

- 오늘의 운세
- 현재 상황
- 지금 필요한 조언
- 상대방의 현재 마음
- 오늘 주의해야 할 부분

한 장 리딩의 카드 위치 이름은 다음과 같이 설정한다.

```text
현재의 메시지
```

또는 선택 주제에 따라 다음과 같이 변경할 수 있다.

```text
오늘의 핵심 흐름
현재 필요한 조언
상대방의 현재 마음
```

---

## 6.2 세 장 리딩

카드 세 장을 선택한다.

현재 상황의 원인, 흐름, 앞으로의 가능성을 비교적 구체적으로 해석한다.

기본 구조:

- 첫 번째 카드: 과거 또는 원인
- 두 번째 카드: 현재 상황
- 세 번째 카드: 미래 흐름 또는 조언

연애운에서는 다음 구조를 사용할 수 있다.

- 첫 번째 카드: 나의 마음
- 두 번째 카드: 상대방의 마음
- 세 번째 카드: 관계의 흐름

진로운에서는 다음 구조를 사용할 수 있다.

- 첫 번째 카드: 현재 나의 상태
- 두 번째 카드: 기회와 장애물
- 세 번째 카드: 앞으로의 방향

재물운에서는 다음 구조를 사용할 수 있다.

- 첫 번째 카드: 현재 재정 상태
- 두 번째 카드: 주의해야 할 부분
- 세 번째 카드: 앞으로의 흐름

---

## 6.3 일곱 장 리딩

카드 일곱 장을 선택한다.

보다 자세하고 세밀한 분석을 원하는 사용자를 위한 리딩이다.

카드 수 선택 화면에 다음 안내 문구를 표시한다.

> 카드 수가 증가할수록 상황을 더욱 세밀하게 살펴볼 수 있습니다.

일곱 장 리딩의 기본 구조:

1. 현재 상황
2. 과거의 영향
3. 숨겨진 감정 또는 원인
4. 현재의 장애물
5. 도움이 되는 요소
6. 가까운 미래의 흐름
7. 최종 조언

연애운의 일곱 장 구조:

1. 나의 현재 마음
2. 상대방의 현재 마음
3. 관계의 과거 흐름
4. 현재 관계의 장애물
5. 관계에 도움이 되는 요소
6. 가까운 미래의 변화 가능성
7. 관계에 대한 최종 조언

진로운의 일곱 장 구조:

1. 현재 진로 상태
2. 나의 강점
3. 나의 약점 또는 불안 요소
4. 현재 마주한 장애물
5. 활용할 수 있는 기회
6. 가까운 미래의 흐름
7. 실천해야 할 조언

일곱 장 리딩은 결과가 길어질 수 있으므로 각 카드 설명을 지나치게 길게 생성하지 않도록 한다.

# 7. 카드 수 선택 UI

카드 수 선택 화면에는 다음 세 가지 선택지를 카드 형태로 표시한다.

```text
한 장 리딩
빠르게 핵심 메시지를 확인합니다.

세 장 리딩
상황의 원인, 현재, 앞으로의 흐름을 확인합니다.

일곱 장 리딩
여러 요소를 연결하여 더욱 세밀하게 해석합니다.
```

화면 하단에는 다음 문구를 표시한다.

> 카드 수가 증가할수록 상황을 더욱 세밀하게 살펴볼 수 있습니다.

선택된 카드 배열은 금색 테두리와 빛 효과로 강조한다.

선택이 완료되기 전에는 `다음 단계` 버튼을 비활성화한다.

# 8. 카드 셔플 기능

## 8.1 셔플 시작

사용자가 상담 주제와 카드 배열을 선택한 뒤 `카드 섞기` 버튼을 누르면 셔플 애니메이션을 실행한다.

셔플 애니메이션은 단순히 로딩 아이콘을 보여주는 방식이 아니라 실제 여러 장의 카드가 섞이는 듯한 느낌을 줘야 한다.

가능한 애니메이션:

- 카드들이 좌우로 빠르게 이동한다.
- 카드 덱이 두 묶음으로 나뉜다.
- 두 카드 묶음이 서로 교차한다.
- 카드들이 겹쳤다가 다시 퍼진다.
- 카드 일부가 위아래로 움직인다.
- 마지막에는 카드가 하나의 덱으로 합쳐진다.
- 셔플이 끝나면 카드들이 부채꼴 또는 가로 형태로 펼쳐진다.

셔플 시간은 약 2초에서 3초 사이로 설정한다.

셔플 도중에는 사용자가 카드를 선택하지 못하게 한다.

---

## 8.2 셔플 안내 문구

셔플 도중 다음 문구를 무작위로 하나씩 표시한다.

- 카드에 마음을 집중해보세요.
- 당신의 질문을 조용히 떠올려보세요.
- 카드가 당신의 현재 흐름을 읽고 있습니다.
- 마음이 이끄는 카드를 선택해보세요.
- 서두르지 말고 카드의 움직임을 바라보세요.

문구는 일정 시간마다 부드럽게 변경될 수 있다.

---

## 8.3 셔플 기술 구현

셔플 애니메이션은 다음 중 하나를 사용한다.

- Framer Motion
- CSS Animation
- GSAP
- React 상태와 CSS Transform 조합

기본적으로 Framer Motion을 우선 사용한다.

과도하게 무거운 애니메이션으로 사이트 성능이 저하되지 않도록 한다.

`prefers-reduced-motion` 설정을 확인하여 애니메이션 감소를 선호하는 사용자에게는 단순한 전환 효과를 제공한다.

# 9. 카드 선택 기능

셔플이 끝나면 카드 뒷면들이 화면에 펼쳐져야 한다.

사용자가 직접 원하는 카드를 클릭하거나 터치하여 선택할 수 있어야 한다.

## 9.1 카드 선택 규칙

- 한 장 리딩에서는 한 장만 선택할 수 있다.
- 세 장 리딩에서는 세 장까지 선택할 수 있다.
- 일곱 장 리딩에서는 일곱 장까지 선택할 수 있다.
- 같은 카드를 중복 선택할 수 없다.
- 이미 선택한 카드를 다시 누르면 선택을 취소할 수 있다.
- 선택 순서가 카드 위치 순서가 된다.
- 선택된 카드에는 빛나는 테두리와 상승 효과를 적용한다.
- 선택된 카드 위에 선택 순서를 숫자로 표시한다.
- 필요한 카드 수를 모두 선택하면 `선택 완료` 버튼이 활성화된다.
- 필요한 카드 수보다 적게 선택한 경우 `선택 완료` 버튼은 비활성화된다.

선택 상태 예시:

```text
3장 중 2장을 선택했습니다.
```

```text
7장 중 5장을 선택했습니다.
```

---

## 9.2 선택 카드 효과

선택된 카드에는 다음 효과를 적용한다.

- 카드가 위로 약간 올라간다.
- 카드 테두리가 금색으로 빛난다.
- 카드 주변에 은은한 그림자 효과가 나타난다.
- 선택 순서 번호가 카드 상단에 표시된다.
- 선택 시 짧고 부드러운 효과음을 재생할 수 있도록 구조를 준비한다.

선택하지 않은 카드에는 지나치게 강한 효과를 적용하지 않는다.

---

# 10. 카드 랜덤 처리

카드 결과는 사용자가 카드를 선택한 시점에 결정되는 것처럼 느껴져야 한다.

단순히 화면에 표시된 순서대로 고정된 카드가 나오면 안 된다.

셔플을 시작할 때 전체 타로 덱을 무작위로 섞고, 각 카드 위치에 실제 카드 데이터를 연결한다.

같은 리딩 안에서는 동일한 카드가 두 번 선택되지 않도록 한다.

정방향과 역방향은 각 카드가 선택될 때 또는 덱을 셔플할 때 무작위로 결정한다.

정방향과 역방향 확률은 기본적으로 다음처럼 설정한다.

```text
정방향: 70%
역방향: 30%
```

추후 설정에서 역방향 카드 사용 여부를 켜거나 끌 수 있도록 구조를 분리한다.

무작위 처리에는 다음 함수를 사용할 수 있다.

```typescript
function shuffleArray<T>(items: T[]): T[] {
  const copiedItems = [...items];

  for (let i = copiedItems.length - 1; i > 0; i -= 1) {
    const randomIndex = Math.floor(Math.random() * (i + 1));

    [copiedItems[i], copiedItems[randomIndex]] = [
      copiedItems[randomIndex],
      copiedItems[i],
    ];
  }

  return copiedItems;
}
```

보안이 중요한 추첨이 아니므로 기본 `Math.random()`을 사용할 수 있다.

# 12. 카드 공개 애니메이션

사용자가 카드 선택을 완료하면 선택한 카드가 화면 중앙의 리딩 영역으로 이동한다.

그다음 카드가 한 장씩 뒤집히는 플립 애니메이션을 실행한다.

카드 공개 효과:

- 카드가 Y축을 기준으로 회전한다.
- 카드 뒷면에서 앞면으로 자연스럽게 전환된다.
- 카드 공개 시 은은한 금색 빛이 퍼진다.
- 작은 별 또는 입자 효과를 표시한다.
- 카드 이름을 카드 아래에 표시한다.
- 카드 위치 이름을 함께 표시한다.
- 정방향 또는 역방향을 명확하게 표시한다.
- 역방향 카드라면 카드 이미지를 180도 회전하여 보여준다.

세 장 리딩 공개 순서:

1. 첫 번째 카드 공개
2. 약 0.5초 후 두 번째 카드 공개
3. 약 0.5초 후 세 번째 카드 공개
4. 모든 카드 공개 후 AI 해석 시작

일곱 장 리딩 공개 순서:

1. 첫 번째 카드부터 순서대로 공개
2. 각 카드 사이에 약 0.3초 간격 적용
3. 전체 공개가 끝난 뒤 AI 해석 시작
4. 모바일에서는 화면이 선택 카드 영역을 따라 자연스럽게 이동하도록 처리

애니메이션 도중에는 중복 버튼 클릭을 막는다.

# 16. Gemini 프롬프트 작성 원칙

서버에서 Gemini에 전달할 시스템 지침 또는 기본 프롬프트에는 다음 내용을 포함한다.

# 17. AI 해석 작성 원칙

AI는 미래를 확정적으로 예언하면 안 된다.

피해야 하는 표현:

- 반드시 연락이 옵니다.
- 무조건 재회합니다.
- 이 사람은 당신을 사랑합니다.
- 다음 달에 합격합니다.
- 큰돈을 벌게 됩니다.
- 사고가 발생합니다.
- 관계는 반드시 끝납니다.
- 임신하게 됩니다.
- 병이 생겼습니다.

권장 표현:

- 연락 가능성이 열려 있는 흐름으로 볼 수 있습니다.
- 관계 회복의 여지는 있지만 소통 방식이 중요해 보입니다.
- 재정적으로 새로운 기회를 검토하게 될 가능성이 있습니다.
- 상대방이 현재 감정을 정리하는 시간이 필요할 수 있습니다.
- 현재 준비 상태와 선택에 따라 결과가 달라질 수 있습니다.
- 이 카드는 결정을 서두르지 말라는 조언으로 해석할 수 있습니다.

상대방의 마음도 사실처럼 단정하지 않는다.

잘못된 예시:

```text
상대방은 아직 당신을 사랑하고 있습니다.
```

올바른 예시:

```text
이 카드의 상징을 기준으로 보면 상대방에게 아직 정리되지 않은 감정이 남아 있을 가능성으로 해석할 수 있습니다.
```

# 22. Gemini JSON 응답 처리

Gemini가 항상 완벽한 JSON만 반환한다고 가정하지 않는다.

다음 상황을 처리한다.

- JSON 앞뒤에 설명 문장이 포함된 경우
- 마크다운 코드 블록이 포함된 경우
- 일부 필드가 누락된 경우
- 잘못된 따옴표가 포함된 경우
- 응답이 빈 문자열인 경우
- 응답이 지나치게 긴 경우

서버에서는 다음 순서로 처리한다.

1. Gemini 응답 텍스트 확인
2. ```json 코드 블록 제거
3. 첫 번째 `{`부터 마지막 `}`까지 추출
4. `JSON.parse()` 시도
5. 필수 필드 검증
6. 실패하면 fallback 해석 반환

잘못된 응답 때문에 서버가 종료되지 않도록 `try-catch`를 사용한다.

# 23. API 키가 없는 경우의 Fallback 처리

Gemini API 키가 설정되지 않았더라도 사이트의 카드 선택과 결과 화면을 테스트할 수 있어야 한다.

`GEMINI_API_KEY`가 비어 있으면 서버는 미리 준비된 기본 해석을 반환한다.

예시:

```typescript

        ? `${card.koreanName} 카드는 ${card.keywords.join(", ")}의 흐름을 중심으로 살펴볼 수 있습니다.`
        : `${card.koreanName} 역방향 카드는 현재 상황에서 속도를 조절하고 놓치고 있는 부분을 다시 살펴보라는 메시지로 해석할 수 있습니다.`,
  })),
  connection:
    "선택된 카드들은 현재의 감정과 현실적인 조건을 함께 살펴보는 것이 중요하다는 흐름을 보여줍니다.",
```

# 24. API 오류 처리

다음 오류를 처리한다.

## API 키 누락

```text
GEMINI_API_KEY가 설정되지 않았습니다.
```

사용자 화면에서는 fallback 해석을 표시한다.

사용자 메시지:

HTTP 상태 코드:

```text
429
```

사용자 메시지:

HTTP 상태 코드:

```text
500
```

사용자 메시지:

> 타로 해석을 불러오지 못했습니다. 잠시 후 다시 시도해주세요.

## 네트워크 오류

사용자 메시지:

> 서버에 연결할 수 없습니다. 인터넷 연결을 확인한 뒤 다시 시도해주세요.

# 26. 프론트엔드 API 요청

프론트엔드에서는 별도의 서비스 파일을 사용한다.

예시 파일:

```text
src/services/tarotApi.ts
```

예시 코드:

```typescript
import type {
  TarotReadingRequest,
  TarotReadingResult,
} from "../types/tarot";

export async function requestTarotReading(
  payload: TarotReadingRequest,
): Promise<TarotReadingResult> {
  const response = await fetch("/api/tarot/reading", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(payload),
  });

  const result = await response.json();

  if (!response.ok || !result.success) {
    throw new Error(
      result?.error?.message ||
        "타로 해석을 불러오지 못했습니다.",
    );
  }

  return result.data;
}
```

Gemini API 키를 프론트엔드 코드에 넣지 않는다.

다음과 같은 코드는 절대로 사용하지 않는다.

```typescript
const apiKey = import.meta.env.VITE_GEMINI_API_KEY;
```

Vite에서 `VITE_`로 시작하는 환경변수는 브라우저에 노출될 수 있으므로 비밀 키에 사용하면 안 된다.

- 일곱 장 리딩은 4장과 3장 또는 가로 7장 구조로 배치한다.

## 모바일 화면

- 카드 크기를 줄인다.
- 카드 선택 영역에 가로 스크롤을 적용할 수 있다.
- 카드가 지나치게 겹쳐 터치하기 어렵지 않도록 한다.
- 터치한 카드가 확실히 선택되도록 한다.
- 버튼은 엄지손가락으로 누르기 편한 크기로 만든다.
- 결과 본문의 글자 크기를 최소 15px 이상으로 유지한다.
- 일곱 장 결과는 세로로 자연스럽게 내려가며 확인할 수 있도록 한다.
- 버튼 영역은 화면 하단에 고정할 수 있지만 콘텐츠를 가리지 않도록 한다.

# 39. 보안 요구사항

Gemini API 키를 프론트엔드 코드에 직접 작성하지 않는다.

다음과 같은 코드는 사용하면 안 된다.

```typescript
const apiKey = "실제-Gemini-API-키";
```

다음과 같은 방식도 사용하면 안 된다.

```env
VITE_GEMINI_API_KEY=실제키
```

`VITE_` 환경변수는 브라우저 번들에 포함될 수 있다.

API 요청은 반드시 별도의 Node.js 백엔드에서 처리한다.

추가 보안 요구사항:

- `.env`를 `.gitignore`에 추가한다.
- 실제 API 키를 로그에 출력하지 않는다.
- 오류 응답에 API 키나 내부 프롬프트를 포함하지 않는다.
- 사용자 입력 길이를 제한한다.
- 요청 횟수를 제한한다.
- JSON body 크기를 제한한다.
- CORS 설정을 필요한 주소로 제한한다.
- 운영 환경에서는 HTTPS를 사용한다.
- API 키가 유출되었다면 즉시 기존 키를 폐기하고 새 키를 생성한다.

# 46. 기존 OpenAI 코드가 있을 경우 수정 지시

현재 프로젝트에 OpenAI API 관련 코드가 이미 있다면 다음 작업을 수행한다.

1. OpenAI SDK 사용 코드를 찾는다.
2. 더 이상 사용하지 않는 OpenAI SDK를 제거한다.
3. `OPENAI_API_KEY` 환경변수를 제거한다.
4. `OPENAI_MODEL` 환경변수를 제거한다.
5. Gemini 환경변수로 변경한다.
6. OpenAI API 호출 코드를 Gemini 공식 SDK 호출로 변경한다.
7. 기존 프론트엔드 API 경로는 가능한 한 유지한다.
8. 기존 카드 셔플, 카드 선택, 카드 공개 기능은 변경하지 않는다.
9. 기존 UI 디자인이 정상이라면 최대한 유지한다.
10. 기존 OpenAI 응답 타입을 새로운 Gemini 응답 구조에 맞춰 수정한다.
11. `.env.example`을 Gemini 기준으로 수정한다.
12. README 또는 실행 안내도 Gemini 기준으로 수정한다.

변경 전:

```env
OPENAI_API_KEY=sk-your-api-key
OPENAI_MODEL=gpt-5-mini
PORT=8787
```

변경 후:

```env
GEMINI_API_KEY=your-gemini-api-key
GEMINI_MODEL=gemini-2.5-flash
PORT=8787
```

# 51. 최종 목표

최종 결과물은 단순히 AI에게 질문하고 텍스트 답변을 받는 사이트가 아니다.

사용자가 다음 경험을 할 수 있어야 한다.

1. 신비로운 타로점 공간에 들어온다.
2. 원하는 상담 주제를 선택한다.
3. 자신의 질문을 떠올리거나 입력한다.
4. 원하는 카드 수를 선택한다.
5. 실제로 카드가 섞이는 모습을 본다.
6. 펼쳐진 카드 중 마음이 가는 카드를 직접 고른다.
7. 선택한 카드가 한 장씩 공개된다.
8. 카드들의 상징이 서로 연결된 AI 해석을 받는다.
9. 결과를 저장하거나 다시 리딩을 진행한다.

가장 중요한 것은 다음 세 가지다.

```text
사용자가 직접 카드를 선택하는 경험
실제 타로점 같은 몰입감 있는 디자인
선택한 카드와 질문을 연결하는 자연스러운 AI 해석
```

디자인은 평범한 카드 게임처럼 만들지 않는다.

사용자가 실제 신비로운 타로점 안에서 카드를 고르고 메시지를 전달받는 듯한 경험을 느낄 수 있도록 제작한다.
