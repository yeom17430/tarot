# 78장 전체 덱 및 리본 스프레드 카드 선택 UI 개선 요구사항

## 1. 수정 목적

현재 카드 선택 화면에 전체 78장이 표시되지 않으며, 카드가 작거나 과도하게 겹쳐 있어 사용자가 원하는 카드를 선택하기 어렵다.

카드 선택 화면을 실제 카드 마술사가 테이블 위에 덱을 길게 펼치는 것과 같은 리본 스프레드 형태로 수정한다.

가장 중요한 요구사항은 다음과 같다.

1. 타로 카드 데이터가 총 78장이어야 한다.
2. 카드 선택 대상도 실제로 78장 전체여야 한다.
3. 78장의 카드 뒷면을 가로 리본 스프레드 형태로 표시한다.
4. 사용자는 마우스 드래그, 휠 또는 모바일 스와이프로 전체 덱을 탐색할 수 있어야 한다.
5. 각 카드는 선택하기 쉽게 호버 또는 터치 반응을 제공한다.
6. 선택한 카드는 상단의 별도 선택 슬롯으로 이동해야 한다.
7. 기존 셔플, 플립, Gemini 해석 기능은 망가뜨리지 않는다.

# 2. 전체 덱 검증

현재 `src/data/tarotCards.ts` 또는 카드 데이터 파일을 확인한다.

전체 카드 데이터는 반드시 다음 구성으로 총 78장이어야 한다.

```text
메이저 아르카나: 22장
완드: 14장
컵: 14장
소드: 14장
펜타클: 14장
총합: 78장
```

개발 환경에서 다음 검증을 추가한다.

```typescript
if (tarotCards.length !== 78) {
  console.warn(
    `타로 카드 데이터가 78장이 아닙니다. 현재 ${tarotCards.length}장입니다.`,
  );
}
```

ID는 중복되면 안 된다.

```typescript
const uniqueIds = new Set(tarotCards.map((card) => card.id));

if (uniqueIds.size !== tarotCards.length) {
  console.warn("중복된 타로 카드 ID가 있습니다.");
}
```

카드 이름, 이미지 경로, 정방향 키워드, 역방향 키워드가 누락되지 않았는지 확인한다.

# 3. 셔플 처리

리딩을 시작할 때 78장 전체를 Fisher-Yates 방식으로 섞는다.

```typescript
export function shuffleArray<T>(items: T[]): T[] {
  const result = [...items];

  for (let index = result.length - 1; index > 0; index -= 1) {
    const randomIndex = Math.floor(Math.random() * (index + 1));

    [result[index], result[randomIndex]] = [
      result[randomIndex],
      result[index],
    ];
  }

  return result;
}
```

셔플된 78장 전체를 `shuffledCards` 상태에 저장한다.

```typescript
const shuffledDeck = shuffleArray(tarotCards);
setShuffledCards(shuffledDeck);
```

화면에 일부 카드만 임의로 잘라서 보여주지 않는다.

다음과 같은 코드를 사용하고 있다면 제거한다.

```typescript
shuffledCards.slice(0, 15)
```

```typescript
shuffledCards.slice(0, 22)
```

```typescript
shuffledCards.slice(0, visibleCardCount)
```

카드 선택 영역에는 78장 전체를 렌더링한다.

# 4. 리본 스프레드 UI

카드 선택 화면을 가로 방향의 리본 스프레드로 변경한다.

사용자가 보게 되는 형태:

```text
[카드][카드][카드][카드][카드][카드]...
```

각 카드는 일정 부분 겹친다.

PC 기본값:

```text

카드 높이: 198px
카드 간 이동 간격: 28px
```

모바일 기본값:

# 5. 카드 위치 계산

카드마다 absolute positioning 또는 Framer Motion을 사용하여 겹친 형태로 배치한다.

각 카드의 기본 위치는 다음과 같이 계산한다.

```typescript
const overlapStep = isMobile ? 48 : 28;
const left = index * overlapStep;
```

전체 스프레드 너비:

```typescript
const spreadWidth =
  (cards.length - 1) * overlapStep + cardWidth;
```

카드 전체가 약한 곡선을 이루도록 Y 위치와 회전을 추가한다.

```typescript
const normalized =
  cards.length <= 1 ? 0.5 : index / (cards.length - 1);

const distanceFromCenter =
  Math.abs(normalized - 0.5) * 2;

const translateY = distanceFromCenter * 18;
const rotate = (normalized - 0.5) * 8;
```

78장을 완전한 반원 부채꼴로 만들지 않는다.

약한 아치 형태의 가로 리본 스프레드를 사용한다.

# 6. 카드 호버 동작

PC에서 카드 위에 마우스를 올리면 다음 효과를 적용한다.

1. 해당 카드가 위로 28~36px 올라간다.
2. 카드 크기가 약 1.04배 커진다.
3. `z-index`가 증가하여 주변 카드 위에 표시된다.
4. 금색 테두리가 은은하게 나타난다.
5. 주변 카드와 구분되도록 그림자를 추가한다.
6. 포인터가 어떤 카드를 가리키는지 명확하게 표시한다.

예시:

```typescript
animate={{
  y: isHovered ? baseY - 32 : baseY,
  rotate: isHovered ? 0 : baseRotation,
  scale: isHovered ? 1.04 : 1,
  zIndex: isHovered ? 200 : index,
}}
```

호버된 카드는 전체 카드 너비를 확인할 수 있도록 주변 카드보다 앞으로 표시한다.

# 7. 카드 선택 동작

카드를 클릭하거나 터치하면 해당 카드를 선택한다.

선택 규칙:

- 한 장 리딩: 최대 1장
- 세 장 리딩: 최대 3장
- 일곱 장 리딩: 최대 7장
- 같은 카드를 중복 선택할 수 없다.
- 선택된 카드를 다시 누르면 선택을 취소할 수 있다.
- 선택 순서가 카드 위치 순서가 된다.
- 아직 공개 전이므로 카드 앞면을 표시하지 않는다.

선택된 카드에는 다음 정보를 저장한다.

```typescript
{
  ...card,
  selectionOrder: selectedCards.length + 1,
  orientation: Math.random() < 0.3 ? "reversed" : "upright"
}
```

선택된 카드에는 다음 효과를 적용한다.

- 스프레드에서 위로 더 크게 올라간다.
- 금색 테두리를 표시한다.
- 선택 순서 번호를 표시한다.
- 원래 자리에는 어두운 오버레이 또는 선택 표시를 보여준다.

---

# 8. 선택 슬롯 영역

리본 스프레드 위쪽에 선택한 카드를 보여주는 별도 슬롯을 추가한다.

한 장 리딩:

```text
[현재의 메시지]
```

세 장 리딩:

```text
[과거/원인] [현재 상황] [미래/조언]
```

일곱 장 리딩:

```text
[현재 상황] [과거 영향] [숨은 원인] [장애물]
[도움 요소] [가까운 미래] [최종 조언]
```

선택한 카드가 해당 슬롯으로 이동하는 애니메이션을 적용한다.

카드 앞면은 공개하지 않는다.

슬롯에는 카드 뒷면과 선택 번호만 표시한다.

선택을 취소하면 해당 슬롯이 다시 빈 상태로 돌아간다.

# 9. 드래그 및 스와이프

PC에서는 다음 방법으로 탐색할 수 있어야 한다.

- 마우스 드래그
- 트랙패드 가로 스크롤
- 마우스 휠
- 좌우 화살표 버튼
- 키보드 좌우 방향키

모바일에서는 손가락으로 좌우 스와이프할 수 있어야 한다.

드래그 중에는 카드가 실수로 선택되지 않도록 이동 거리 기준을 둔다.

예시:

```typescript
const DRAG_THRESHOLD = 6;
```

포인터가 6px 이상 이동했다면 클릭 선택으로 처리하지 않는다.

# 10. 휠 가로 이동

카드 스프레드 영역에 마우스가 있을 때 세로 휠 입력으로 가로 이동할 수 있도록 한다.

```typescript
function handleWheel(
  event: React.WheelEvent<HTMLDivElement>,
) {
  if (Math.abs(event.deltaY) <= Math.abs(event.deltaX)) {
    return;
  }

  event.currentTarget.scrollLeft += event.deltaY;
  event.preventDefault();
}
```

페이지 전체 스크롤을 지나치게 방해하지 않도록 카드 영역 내부에서만 적용한다.

# 11. 카드 선택 안내

선택 화면 상단에 다음 문구를 표시한다.

```text
78장의 카드를 모두 섞었습니다.
마음이 가는 카드를 직접 선택해보세요.
```

선택 진행 상태:

```text
전체 78장 · 선택 2/3
```

하단 안내:

```text
카드를 좌우로 드래그하거나 스와이프해서 살펴보세요.
마우스를 올리면 카드가 위로 올라옵니다.
```

모바일에서는 다음처럼 표시한다.

```text
좌우로 밀어서 카드를 살펴본 뒤 원하는 카드를 눌러주세요.
```

# 12. 스크롤 위치 초기화

셔플 완료 후 카드 스프레드가 항상 한쪽 끝에서 시작하지 않도록 한다.

사용자가 덱 가운데부터 탐색할 수 있도록 컨테이너의 중앙 부근으로 이동한다.

```typescript
requestAnimationFrame(() => {
  const element = spreadRef.current;

  if (!element) {
    return;
  }

  element.scrollLeft =
    (element.scrollWidth - element.clientWidth) / 2;
});
```

또는 시작 위치를 무작위로 설정할 수 있다.

다만 선택 결과는 화면 시작 위치와 무관하게 이미 셔플된 덱 데이터에 따라 결정되어야 한다.

# 13. 접근성

각 카드 선택 버튼에는 다음과 같은 레이블을 사용한다.

```text
78장 중 24번째 카드 선택
```

카드 앞면은 공개 전이므로 카드 이름을 `aria-label`에 넣지 않는다.

예시:

```typescript
aria-label={`78장 중 ${index + 1}번째 카드 ${
  isSelected ? "선택 취소" : "선택"
}`}
```

키보드 사용자는 Tab으로 카드를 이동할 수 있어야 한다.

Enter 또는 Space로 카드를 선택할 수 있어야 한다.

현재 포커스된 카드는 명확한 테두리로 표시한다.

# 14. 성능

78장을 렌더링하는 것은 React에서 충분히 처리할 수 있다.

다만 다음을 적용한다.

- 카드 앞면 이미지는 선택 또는 공개 전까지 로딩하지 않는다.
- 선택 화면에서는 동일한 카드 뒷면 이미지만 사용한다.
- 카드 컴포넌트를 `React.memo`로 최적화한다.
- 마우스 이동마다 전체 78장을 다시 렌더링하지 않는다.
- hover 상태를 가능한 한 CSS로 처리한다.
- 불필요하게 큰 원본 이미지를 사용하지 않는다.
- 입자 애니메이션 개수를 모바일에서 줄인다.

카드 선택 화면에서 카드 앞면 정보가 사용자에게 노출되지 않도록 한다.
